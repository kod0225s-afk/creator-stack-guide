# チーム運用ルール

対象: Creator Stack Guide 運用チーム

このドキュメントは、AI動画ツール比較アフィリエイトサイトの運用を部署単位に分け、ユーザーへの報告を秘書が一本化するための運用ルールです。

## 1. 基本方針

- ユーザーへ各部署から直接バラバラに報告しない。
- ユーザーへの報告は原則として `秘書` がまとめる。
- 各部署は「成果物」「判断が必要な点」「リスク」だけを秘書へ渡す。
- 秘書は、ユーザーが判断すべき内容だけを短く整理して共有する。
- タスクは `docs\TICKET_BOARD.md` でチケット管理し、秘書が状態を更新する。
- 無料運用を前提にする。有料サーバー、有料ドメイン、有料広告はユーザー確認なしに進めない。
- 未承認のアフィリエイトリンクを成果リンクとして公開しない。
- 実測していない内容を「使ってみた」「検証済み」と書かない。
- Search Console、ASP、Google、外部アカウントの確定操作はユーザー確認を挟む。

## 2. 部署構成

| 部署 | 主担当 | 成果物 |
|---|---|---|
| 企画・編成 | 狙うキーワード、記事順、収益導線 | 優先キーワード、記事計画、導線案 |
| リサーチ・条件確認 | 公式価格、無料プラン、報酬条件 | 確認URL、変更点、注意点 |
| 実測レビュー | ツール試用、作成時間、透かし確認 | 実測メモ、スクリーンショット、サンプル動画 |
| SEO・記事編集 | 構成、見出し、内部リンク、表現調整 | 記事本文、比較表、FAQ、メタ情報 |
| アフィリエイト管理 | 承認状況、成果リンク、広告表記 | 承認リンク一覧、差し替えメモ、広告表記確認 |
| デザイン・UI | 読みやすさ、スマホ表示、比較表 | UI改善案、CSS調整、表示確認 |
| 公開・Search Console | GitHub Pages、sitemap、robots、URL検査 | 公開確認、Search Console確認メモ |
| セキュリティ・法務 | CSP、プライバシー、広告表記、禁止表現 | セキュリティ確認、表記チェック |
| QA・検収 | 文字化け、リンク切れ、placeholder、表示崩れ | 検収結果、修正指示 |
| 集客・Growth | X、note、Shorts概要欄、無料送客 | 投稿案、導線文、反応メモ |
| アナリティクス・改善 | Search Console、PV、クリック、順位 | 数値メモ、改善仮説 |
| システム・安全管理 | 生成スクリプト、Git、未コミット差分 | ビルド確認、差分整理、事故防止 |
| 秘書 | 報告統合、判断整理、チケット管理 | ユーザー向け要約、確認依頼 |

## 3. 秘書の役割

秘書は全体の窓口です。

ユーザーへ出す報告は以下に絞る。

- 現在の状態
- ユーザー判断が必要なこと
- 公開や収益に関わるリスク
- 完了した成果物
- 次にやるべきP0

秘書は以下をユーザーに流さない。

- 各部署の細かい作業ログ
- 内部検討の途中案
- すでに解決済みの軽微なエラー
- ユーザー判断が不要な進捗メモ

## 4. 報告フォーマット

秘書がユーザーへ出す標準形:

```text
現状:
- どこまで進んだか

確認してほしいこと:
- ユーザー判断が必要な点だけ

成果物:
- 追加/修正したファイル
- 公開URLや確認URL

リスク:
- 未確認、未承認、文字化け、Search Consoleなど

次の動き:
- 続ける部署とP0タスク
```

## 4.5 チケット管理

チケット管理は `docs\TICKET_BOARD.md` を正とする。

- 新しい依頼が来たら、秘書が必要に応じてチケットを追加する。
- 作業に入ったら `Doing`、検収中は `Review`、ユーザー操作待ちは `Waiting` にする。
- 完了したら `Done` に移す。
- ユーザーへ毎回チケット全件を報告しない。
- 報告対象は P0、Blocked、ユーザー操作待ち、判断待ちに絞る。
- チケットには部署、期限、次のアクション、完了条件を持たせる。

## 5. 運用フロー

1. 秘書が `docs\TICKET_BOARD.md` を確認する。
2. システム・安全管理が `git status --short` を確認する。
3. 未コミット差分がある場合は、意図不明な差分を触らずにリスクとして記録する。
4. 企画・編成がP0/P1の優先順位を決める。
5. リサーチ・条件確認が公式情報を確認する。
6. 実測レビューが無料範囲でツールを試す。
7. SEO・記事編集が実測と公式情報だけを本文へ反映する。
8. アフィリエイト管理が承認済みリンクだけを差し替える。
9. デザイン・UIが比較表やスマホ表示を確認する。
10. 公開・Search Consoleがsitemap、robots、URL検査を確認する。
11. QA・検収がplaceholder、文字化け、リンク切れ、広告表記を確認する。
12. 秘書がユーザーへ判断事項だけをまとめて報告する。

## 6. エスカレーション

秘書が必ずユーザーへ確認するもの:

- 有料サービスを使う場合
- 独自ドメインを購入する場合
- ASPやGoogleなど外部アカウントで確定操作をする場合
- 成果リンクを公開導線に追加する場合
- Search ConsoleやASPで個人情報・支払い情報が絡む場合
- 実測前の内容を強い訴求に変える場合
- 既存の未コミット差分を戻す必要がある場合

秘書が内部処理してよいもの:

- 進捗/引き継ぎメモ更新
- チケット状態の更新
- 公式URL確認メモの追加
- 軽微な誤字修正
- 検収結果の記録
